Security and access control

Least privilege you can watch being enforced

Five role-based identities, five Agent jobs, one audit trail. The result that matters is not that the application can read its own data. It is that the reporting account cannot reach the core tables at all.

2026 breach controls

Four failures from the public record, answered with a test

The March 2026 chain breach exposed 3 TB of payment data after nine undetected days. These are the database-layer controls that break that chain, each demonstrated on this instance. Sources: the published reconstruction and the regulator's investigation.

Backup media is ciphertext

Full backups are written with AES-256 under a server certificate. Restoring the encrypted file with the certificate removed is refused (SQL error 33111); re-importing the key restores it in 0.7 s. A stolen dump is not a data breach.

See the captured output

A failed login is a record

Deliberate bad logins are captured by an extended-events session within seconds, with the client machine and the rejection reason — the answer to a nine-day detection gap.

See the captured output

One identity, one database

The application identity holds no server role, reads one reporting view, and is denied SELECT on the customer and account tables. A blast-radius audit found a connect-only mapping in the payments database from earlier work; it was removed.

See the captured output

No credential in source

The build scans every tracked file for keys, passwords and connection strings. Zero findings across 200+ files, and a planted secret fails the build — so the hardcoded-credential step in the 2026 chain cannot be reintroduced quietly.

Proof

Six checks, both directions

A permission is only real if the allowed action succeeds and the shortcut fails. I ran both sides as the account itself, so the answer came from the engine rather than from my script.

Audit

Every change carries a name

What is recorded

A server audit records every read, insert, update and delete on the account schema: the time, the account that did it, the statement and the object it touched. The files sit outside the data folder, so a mistake in the database cannot overwrite the record of it.

Why it matters

When money moves without a customer asking, the question is who and when. The audit answers both, and a refused attempt never becomes an event, which is why the checks above and the audit cover different ground.

No password is stored in this project. The accounts were created with generated passwords that were never written down or published.

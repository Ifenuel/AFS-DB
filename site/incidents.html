Drills

Ten failures I broke on purpose, then fixed

These ran on the lab instance, not on a customer's money. Each one keeps the engine's own error or diagnostic output from the instance itself, so the proof is the message SQL Server returned, not my summary of it.

INC-001High

Blocking transaction

Writer A holds an X lock on one account row; writer B waits on LCK_M_U, then fails at its lock timeout (1222). Readers were not blocked because READ_COMMITTED_SNAPSHOT is ON — that finding changed the exercise.

Reproducedsys.dm_exec_requests + sys.dm_tran_locks
INC-002High

Deadlock

Two sessions updated the same two accounts in opposite order. SQL Server chose the LOW-priority session as victim (1205) and the HIGH-priority session committed.

ReproducedMsg 1205 in the client output
INC-003Critical

Backup failure

A backup aimed at a non-existent directory failed with 3013 before writing a file. The job would report failure; the watcher would log it.

ReproducedBACKUP ... TO DISK on an invalid path
INC-004Medium

Slow reporting query

YEAR()/MONTH() on the date column versus a half-open range: on the Developer estate the scan reads 20,000 rows in 156 logical reads, the range seek reads 6,695 rows in 63 — same result set, 6,695 rows.

ReproducedSET STATISTICS IO/TIME
INC-005High

Unauthorised access attempt

The reporting login attempted a core table read and was refused at the database boundary (916) before any row was touched.

ReproducedEXECUTE AS LOGIN + error capture
INC-006Medium

Failed deployment

A table creation with a foreign key to a non-existent table failed (1750) and left nothing behind, because the batch is the transaction.

ReproducedTRY/CATCH around DDL
INC-007Critical

Accidental deletion

Ten support cases deleted with their children, then recovered by restoring the full backup plus a log backup to STOPAT before the delete: 130 cases in the live database before, 120 after, 130 in the restored copy.

ReproducedRESTORE ... WITH STOPAT (local time, not UTC)
INC-008High

Storage pressure

An 8 MB capped data file accepted 5,103 rows and then failed with 1105, filegroup full. The alert came from the engine, not from a threshold someone guessed.

ReproducedCREATE DATABASE ... MAXSIZE 8MB + INSERT loop
INC-009High

Service interruption

A session holding an open transaction was killed. The client received Msg 596, the transaction rolled back, and the account balance was unchanged afterwards.

ReproducedKILL <spid> with sys.dm_exec_requests before and after
INC-010Critical

Failed recovery

A backup truncated to 197 KB failed VERIFYONLY with 3203 and RESTORE with 3287; no half-restored database was left behind.

ReproducedRESTORE VERIFYONLY on a truncated file

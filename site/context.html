The problem

One unpatched server became 3 terabytes of stolen payment data

In March 2026 a commercial bank and the country's government payment infrastructure were breached in a single chain. The first academic reconstruction of it is in the Journal of Cyber Security (2026, 8, 357–371). This page is what a database team can actually do about the failures it documents — with the tests, and the limits.

The chain

Five failures, only one of which is a patch

The paper's ablation is the useful part: the remote code execution opened the door, but segmentation was the linchpin. Remove that one control and a pilot server becomes a national incident.

StageWhat failed in 2026What a database team controls
Initial accessInternet-facing pilot server running a framework with a patched RCE (CVE-2025-55182); patch available 47 days before exploitation.Patch cadence is documented as a change, not a hope — and the database does not listen on the internet.
Credential accessEncryption keys in a JavaScript file; database connection strings, cloud keys and client secrets committed to a Git repository.No credential in source; the repository build fails on a secret. Passwords live in a git-ignored secrets store.
Lateral movementDevelopment and pilot systems shared a cluster with production; the trusted peer accepted traffic from the compromised bank.Containment at the database layer: one login, one database, no server role — a compromised application cannot read the audit or fraud estate.
CollectionThree database dumps, 657,242 KYC documents (588 GB), 46 HSM key files and a Git repository with credentials.Encrypted backup media: a dump without the certificate is noise, proven by a restore that is refused.
DetectionNine days of hands-on-keyboard activity, discovered when the actor published it.Failed logins and permission changes recorded with client and reason, queryable by the same SQL that runs the estate.

Oil and gas

Same controls, different plant

Imran et al. (Computers & Security 167, 2026, 104918) interviewed 23 practitioners across Gulf upstream operators and found the IT/OT boundary governed by neither framework cleanly: ISO/IEC 27001 covers the enterprise, IEC 62443 covers the control system, and the seam between them is where process, people and technology fail together. Their framework adds process as a first-class dimension because segmentation on paper did not survive operational pressure.

That is the same conclusion the 2026 breach paper reached from the other direction, and it is testable in a transactional estate: can one identity reach a system it has no business reaching, can a stolen file be read, and would anyone know it happened. The answers here are no, no and yes. What I do not claim: historians, SCADA, safety instrumented systems, the OT network, or any IEC 62443 certification. Those need plant access this lab does not have.

Limits

What this does not cover

GapHonest position
Network segmentationThe estate is one host. Containment is demonstrated at the database layer only; there is no VLAN, firewall zone or jump host to show.
Endpoint and SIEMNo EDR, no log pipeline. Detection here is a SQL extended-events session, which proves the record exists, not that a SOC would act on it.
Key managementThe TDE protector is rotated, exported encrypted to a custody directory outside the instance, and its passphrase is wrapped for the custodian only; an encrypted backup is unreadable once the certificate is dropped. The remaining limitation is hardware: without an HSM or external KMS the custody boundary is a Windows account, not a tamper-resistant device.
SQL authenticationThe instance is Windows-authentication only, so privilege tests use impersonation rather than a live SQL login. Mixed mode would be required to demonstrate a network login path.

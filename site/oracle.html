Oracle lab

A second engine, administered for real

Oracle AI Database 26ai Free runs beside the SQL Server estate, with its own pluggable database, a least-privilege schema, SQL and PL/SQL exercises executed against it through SQL*Plus, and archive-log recovery proven by restoring a deleted row.

Exercises

What ran on the instance

Each item below was executed through SQL*Plus against FREEPDB1 and its output was captured.

Least-privilege user

AFS_LAB was created in FREEPDB1 with CREATE SESSION, TABLE, VIEW, PROCEDURE and SEQUENCE, unlimited quota on USERS, and no roles. The dictionary shows exactly those five grants and nothing else.

Transaction integrity

A two-account transfer created both rows, wrote the matching debit and credit ledger entries in one transaction and committed. Balances moved 1,000 to 900 and 500 to 600 with ledger sums of -100 and +100.

Execution plan

DBMS_XPLAN on the currency and balance query returns TABLE ACCESS FULL with cost 3 and dynamic sampling level 2 — a baseline measured before any index is proposed.

Instance health

Instance status, open mode, PDB state and the listener's registered services were read from v$database, v$pdbs and lsnrctl rather than assumed.

Recovery

A deleted row, brought back by redo

The instance runs in ARCHIVELOG with RMAN backups, and the recovery claim was tested rather than asserted: a committed row was archived, deleted, then recovered from the backup plus archived redo.

Archive log mode

ARCHIVELOG was enabled on 2026-11-24 at 22:07, with a 6 GB fast recovery area. Destination 1 reports VALID, and every log switch produces an archived log — seven were on disk by the next morning.

RMAN, on a schedule

A daily 02:00 task backs up the database plus every archived log, then prunes obsolete sets under a two-day retention. Control-file autobackup is on, the sets are compressed, and the first scheduled run completed with no RMAN or ORA errors.

The drill

A marker row was committed at 22:12:24, archived, then deleted at 22:12:43. FREEPDB1 was restored from the 22:11:44 datafile backup and rolled forward to 22:12:35; the row returned exactly once with its original commit timestamp, and the pluggable database opened read-write again.

Scope of the test

One pluggable database on the same host, restored by RMAN inside the live container, with the task running only while the user is logged on. Oracle Free permits one installation per environment, so the host-loss rebuild was proved on SQL Server instead: core banking restored onto a second instance in 3 s and the TDE-encrypted payments database onto the TDE-capable engine, both with identical row counts.

Method

How the lab is administered

The instance is reached with SQL*Plus over the listener, and every object is created with explicit privileges rather than a broad role grant. Instance state is read from the data dictionary and the listener, so the numbers on this page trace to the running database.
